마크다운을 PDF로 바꿀 때 쪽 나눔이 어긋나는 이유와 맞추는 법

마크다운 보고서를 PDF 로 바꿨더니 표가 두 쪽에 걸쳐 잘리고, 다음 쪽 표에는 머리글이 없고, 섹션 제목만 쪽 맨 아래에 남아 있던 적 있으신가요? 화면과 종이가 글을 배치하는 방식이 다르기 때문이에요.

2026년 11월 26일 · 와타랩스

왜 어긋나나요

화면은 끝없이 이어지는 두루마리예요. 쪽이라는 개념이 없어요. PDF 는 A4 같은 정해진 크기의 종이에 여백을 두고 글을 다시 앉혀요. 이때 세 가지가 달라져요.

  • 글자 크기와 줄 폭 — 화면 폭과 종이 폭이 달라서 같은 문단도 줄 수가 바뀌어요. 줄 수가 바뀌면 쪽이 넘어가는 자리도 바뀌어요.
  • 변환기마다 다른 규칙 — 브라우저 인쇄, 변환 프로그램, 편집기의 내보내기는 쪽을 넘기는 규칙이 저마다 달라요. 같은 문서도 도구에 따라 다른 자리에서 끊겨요.
  • "어디서 끊으면 안 되는지"를 모름 — 사람은 제목과 본문이 한 덩어리라는 걸 알지만, 변환기는 그냥 글자를 위에서부터 채워요. 그래서 제목만 쪽 끝에 남기도 해요.

보기 좋은 쪽 나눔의 규칙

출판물에서 오래 써 온 규칙을 보고서에 옮기면 이렇게 정리돼요.

  1. 제목은 본문과 함께 넘긴다. 제목 아래 본문이 한 줄도 없이 쪽이 끝나면, 제목도 다음 쪽으로 보내요.
  2. 작은 덩어리는 쪼개지 않는다. 블록 제목, 본문, 비고가 남은 자리에 다 안 들어가면 통째로 다음 쪽으로 보내요.
  3. 긴 표는 행 단위로 나누고 머리글을 다시 단다. 다음 쪽 표만 봐도 어떤 열인지 알 수 있어야 해요.
  4. 새 장은 새 쪽에서 — 필요한 경우 섹션마다 새 쪽에서 시작해요.

도구별로 쪽 나눔을 맞추는 방법

브라우저 인쇄 · HTML 을 거치는 변환

마크다운을 HTML 로 바꾼 뒤 인쇄하는 방식이라면, 인쇄용 CSS 로 위 규칙을 적을 수 있어요.

@media print {
  h2, h3 { break-after: avoid; }        /* 제목 바로 뒤에서 끊지 않기 */
  table, figure { break-inside: avoid; } /* 짧은 표 · 그림은 통째로 */
  thead { display: table-header-group; } /* 긴 표의 머리글을 쪽마다 반복 */
  h2 { break-before: page; }             /* 섹션마다 새 쪽(필요할 때만) */
}

다만 브라우저마다 지원 정도가 달라서, 같은 CSS 라도 결과가 조금씩 달라요. 내보낸 PDF 를 열어 직접 확인해야 해요.

원하는 자리에서 직접 넘기기

"여기서는 꼭 새 쪽"인 자리가 있다면 문서에 쪽 나눔 표시를 넣어요. 많은 도구가 HTML 주석 형태를 써요.

미리보기와 PDF 를 똑같이 만드는 방법

가장 확실한 방법은 미리보기가 PDF 를 실제로 그려 본 결과를 보여 주는 것이에요. 와타랩스가 만든 MDitor 라씨가 이렇게 동작해요.

  • 서버가 PDF 를 실제로 그려 보고, 각 블록·항목·표 행이 몇 쪽에 놓이는지 알려 줘요. 미리보기는 그 자리에 쪽 경계를 그려요. 그래서 화면에서 본 대로 PDF 가 나와요.
  • 위의 규칙을 기본으로 따라요. 블록은 남은 자리에 안 들어가면 통째로 다음 쪽으로 가고, 한 쪽보다 큰 표는 행 단위로 나뉘며 머리글이 반복돼요. 한 쪽보다 긴 코드 블록은 줄 단위로 나뉘어요.
  • <!-- pagebreak --> 한 줄로 그 자리에서 쪽을 넘길 수 있어요. 이미 쪽 맨 위라면 빈 쪽을 만들지 않아요.
  • 쪽 설정에서 '섹션마다 새 쪽'을 켜면 ## 마다 새 쪽에서 시작해요. 용지(A4·Letter), 가로·세로, 여백, 글자 크기, 쪽 번호도 고를 수 있어요.

내보내기 전 점검 목록

  • 쪽 맨 아래에 제목만 남은 곳이 없나요?
  • 두 쪽에 걸친 표의 다음 쪽에도 머리글이 있나요?
  • 그림과 그 설명이 다른 쪽으로 떨어지지 않았나요?
  • 쪽 나눔 표시를 넣었다면 그 앞 쪽이 너무 비지 않았나요?
  • 마지막 쪽에 한두 줄만 남았다면, 여백이나 글자 크기를 조금 줄여 한 쪽을 아낄 수 있나요?
